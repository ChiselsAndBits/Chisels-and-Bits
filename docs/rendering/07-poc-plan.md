# 07 – Proof-of-Concept & Rollout Plan

Every phase ships behind a client config flag, `experimentalTerrainRenderer` (default **off** until phase 4), so the existing BakedQuad pipeline stays the fallback until the new path has proven itself. Each phase has a measurable exit criterion.

## Phase 0 – Baseline and test scenes

- Test world (checked in under `docs/rendering/testworld/` or generated by a debug command) with these scenes:
  1. **Worst case:** a 16×16×16 section filled with 3D-checkerboard chiseled blocks.
  2. **Builder detail:** about 1000 realistic chiseled blocks (stairs, trims, carvings).
  3. **Translucency:** mixed glass, stained glass and water bits next to vanilla water.
  4. **Lighting:** inset faces next to torches and glowstone bits, under overhangs, in the Nether.
  5. **Churn:** continuous chiseling (a re-mesh storm).
- Metrics, captured with JFR plus a small debug HUD overlay:
  - section compile time (p50/p99),
  - quads and templates per section/layer,
  - heap allocation rate,
  - FPS,
  - time from a chisel action to the visible update.
- **Exit:** baseline numbers recorded in `docs/rendering/benchmarks.md`.

## Phase 1 – C&B mesher (pure Java, no rendering)

- `ChiseledRenderSnapshot` (built from `StateEntryStorage`), the bitwise face masks, greedy-on-bitplanes, and the per-snapshot rectangle cache ([04](04-mesher.md)).
- The existing async executor builds the snapshot and its rectangles off-thread.
- Unit tests:
  - The **area covered** by the rectangles equals the visible voxel faces from the old `GreedyMeshBuilder`, across random fills and every bit size.
  - Culling against full, empty and chiseled neighbours.
- JMH benchmark against `GreedyMeshBuilder`.
- **Exit:** at least 5× faster meshing, and zero allocation per rectangle.

## Phase 2 – Scena 26.2 vanilla sink (NeoForge + Fabric)

In Scena:
- `TerrainGeometryBlockStateModel`, `ITerrainGeometryContext`, `ITerrainQuadSink.axisAlignedQuad`.
- The `@WrapOperation` hook on `SectionCompiler` → `tesselateBlock` for both loaders ([03](03-scena-api.md)).
- `ITerrainLighter` V1: delegates to the live `BlockModelLighter` ([05](05-lighting.md)).

In C&B:
- `ChiseledBlockStateModel` implements the interface.
- Rectangles → face layers → sink.

**Exit:**
- Screenshots of all scenes match the old path (same pixels, or differences explained and accepted).
- Compile time p99 is at or below baseline.
- No `BakedQuad` is allocated on the terrain path apart from V1's throwaway lighter quads.

## Phase 3 – Sodium sink

- Scena Sodium module:
  - `@WrapOperation` on `BlockRenderer.renderModel`,
  - a native `ChunkVertexEncoder.Vertex[4]` writer,
  - `collector.appendQuad` for translucent quads,
  - `addSprite` for animated textures,
  - lighting via a mutable `ModelQuadView` passed to Sodium's `LightPipeline`.
- **Exit:**
  - All scenes are correct under Sodium.
  - Translucency is sorted by Sodium.
  - FPS is at or above baseline-with-Sodium.

## Phase 4 – Iris / shader packs

- Forward the bit material's `BlockState` through Scena to the Iris block-id context, on both the vanilla and Sodium paths.
- Test with 2–3 popular packs (for example Complementary, BSL, and one that uses `mc_Entity` heavily).
- Check that glass bits are treated as glass, leaf bits wave, and the shadow pass renders C&B geometry.
- **Exit:** shader packs render C&B blocks correctly. **The flag defaults to on** from this phase.

## Phase 5 – 26.4 port

- Scena: retarget to `com.mojang.renderpearl.api`.
- Value-keyed template dedupe.
- Template budget tracking per layer, plus **sharding** for over-budget layers, hooking `extractSectionDrawGroups` / `ChunkSectionsToRender` ([02](02-design.md), [03](03-scena-api.md)).
- The translucent policy from [06](06-translucency.md), including shard re-sorting in `ResortTransparencyTask`.
- **Exit:** the worst-case scene renders completely, with no silent `bakedQuadIndex` overflow, with OIT both on and off.

## Phase 6 – Items, BESR and cleanup

- A `VertexConsumer`-backed sink lets items, held blocks, pattern previews and BESRs share the mesher.
- Remove `ChiseledBlockModelInformationBuilder`, `QuadGenerationUtils` from the terrain path, and the old model-data round trip.
- **Exit:** the old pipeline is deleted, and the flag is removed.

## Phase 7 – Polish

- `ITerrainLighter` V2, an allocation-free re-implementation, gated by golden tests against V1.
- Optional bit-level self-AO setting.

## Risks

| Risk | Mitigation |
|---|---|
| Iris behaviour on 26.4 is unknown | Phase 4 is done on 26.2 first. Re-check when Iris supports 26.4. |
| Fabric API / NeoForge already patch `SectionCompiler` | `@WrapOperation` (MixinExtras) composes with Fabric's `@Redirect`. Covered by a CI smoke test on both loaders. |
| Sodium internals change | The Scena Sodium module is pinned to supported Sodium versions, and a version check disables it (falling back to the old path). |
| Mojang changes the 26.4 format before release | Phase 5 waits for 26.4 pre-releases. The sharding code is isolated in Scena. |
